# Current initialization, DMA containment, command and VIF contract

This gate executes 210 fixed typed observations in six inert static MIPS userspace adapters: initialization61, DMA29, first-arm unwind16, quarantine36, command40 and VIF28. The literal case selectors, expected rows, complete function mappings, model hashes, source inputs and object exports are declared in check_target_init_dma_lifecycle.py. Source generators are parsed as literal data and never imported or called.

The six adapters copy 98 complete function entries (88 distinct functions) in their locked BODY_ORDER, including the unchanged PCI core remove callback. Twenty-eight component source-only function entries and five separate kernel module reference functions are explicitly labeled source-only-not-run; they are not counted as executed C. The input inventory contains 92 logical source entries. Final binding requires 28 distinct actual objects and their 28 commands, with 96 unique required implementation symbols. Static helpers may naturally inline; the gate binds their complete source-model bodies plus actual object/global caller symbols without requiring an unsupported separate ELF symbol claim.

The checked terminal policy retains the complete adapter, ring/token, IRQ, netdev, BAR, PCI device and module owner graph after permanent busy, disable failure or failed idle/reset. It blocks subsequent software re-enable, close/remove release and re-open. Retained drvdata is separately checked to reject another probe before PCI enable. The actual IRQ shim's quarantine guard is bound as source-only evidence and its object/symbol is required. There is no automatic retry or recovery release after the sticky terminal state; independent recovery remains necessary.

Current source whole-function models cover normal/FWDL command descriptor publication under the terminal-state lock, per-owner queued-message take, synchronous completion and asynchronous consumption, packet/metadata cleanup, retry clones and deterministic kick-versus-stop schedules. Firmware completion, queue layout, packet memory and hardware effects remain explicit inert seams. The VIF model checks the serialized INIT→UP caller protocol, duplicate/nonlast owner preservation, failed first UP rollback and close/deinit behavior. The separate native suites additionally run GNU strict compilation, Clang ASan/UBSan and private barrier-removal controls.

The actual kernel module get/put, live-state, reference-release and stop functions, reference base and disabled force-unload branch are bound separately as source-only evidence. CONFIG_MODULES and CONFIG_MODULE_UNLOAD are enabled and CONFIG_MODULE_FORCE_UNLOAD is disabled. Private reference counters do not execute the kernel module unload path. Holding a PCI object reference does not veto physical topology removal or platform resource release; those paths remain outside this software contract.

Early mode uses --trunk PATH --compiler PATH --output PATH/target-init-dma-lifecycle.json --preflight. Final mode replaces --preflight with --wifi-report PATH/target-wifi-factory.json. Final mode requires completed same-source/configuration Factory49, actual built/shipped modules and the same image identity. Every actual object, complete .cmd selection, aggregate/module link command and required unique function symbol must match. This binds a clean full build; compilation and relocation are not independently replayed.

Current module scope is K2P4.4 little-endian MT7615, LINUX, RESOURCE_PRE_ALLOC, ERR_RECOVERY, KTHREAD, tasklet and FAST_PATH_QM. WSC board configuration is disabled and actual commands must not define WSC, CONFIG_PROPRIETARY_DRIVER or RT_BIG_ENDIAN. config.mk defaults do not override the selected board/Makefile/.cmd evidence. Reduced inert preprocessor seams do not execute every enabled AP/ATE/UAPSD/MAT or optional driver branch. The separate WSC native model does not represent shipping MIPS WSC code.

PASS means the fixed selected software observations and source/object/module/image identities match. It does not establish PCI in-flight transaction drain, actual IRQ/RTNL/kernel scheduling safety, all callback/concurrent teardown graphs, physical cold/warm reset, whole-system memory peak or efd2 first-hop execution. MCU queue cleanup assumes registered driver actors are retired before queue locks are freed; arbitrary raw external callers remain outside that actor lifetime proof. Clear-master, busy bits and firmware ACK alone are not hardware drain proof.

No router connection, device/MTD access, firmware write or reboot is performed.
