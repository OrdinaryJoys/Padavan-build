# Built-in initialization and NOR admission contract

This additive gate executes105 fixed inert static MIPS observations: RAETH45, NOR31 and proc29. It copies26 whole functions and records3 source-only functions, with15 logical source inputs. The separate driver-core bus_add_driver guard is source-only. No source generator is executed by the renderer or independent acceptor.

RAETH bookkeeping allocations publish together only after all12 allocations and property/bounds checks. The model retains existing owners on repeat admission, checks failure retry and ndo_uninit ownership, and binds the shipping MAX_RX_RING_NUM4 header and CONFIG_RAETH=y selection. Real raether.o, ra_dbg_proc.o, raeth.o and built-in.o commands/symbols are bound to the same linked kernel. Manual sysfs bind/unbind suppression is checked against the actual driver-core consumer.

NOR admission runs the actual bounded ready loop before permitting another read/write/erase/lock operation. Busy or register errors must leave the new operation unissued and preserve prepare/unprepare operation pairing. Mutex, clock and flash callbacks are private inert seams. Exact operation/FSR enums, deadlines, opcodes and masks are checked against source declarations.

Proc teardown calls the actual thin proc_remove wrapper with an inert subtree traversal/rundown seam. The full real remove_proc_subtree implementation is source-only. Optional diagnostics and changing feature selectors are private variants, not evidence of real kernel callback rundown. Every child failure, duplicate/retry/repeated retirement and parent failure is fixed in the case table.

Six real objects and six .cmd files bind14 unique implementation symbols; the26 whole model entries include helpers which may inline. An actual compiled kernel config is matched byte-for-byte to the embedded config in the independently image-bound kernel. Early MIPS preflight and final same-image SPI reference are mandatory. Static MIPS probes are userspace models, not kernel execution. Physical DMA, active RAETH remove cleanup, MMIO, reset, total memory pressure and old efd2 upgrade execution remain outside this gate.
