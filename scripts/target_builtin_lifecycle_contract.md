# Built-in initialization, runtime, removal and NOR contract

The additive gate executes 563 fixed typed observations in fourteen inert static MIPS models: RAETH45, NOR31, proc29, runtime51, QTX31, ioctl78, reset_core17, MDIO34, remove20, ESW32, reset_lifecycle48 esw_vlan68, shutdown27 and phy_poll52. All 484 preceding observations remain unchanged. It renders 183 complete function entries, 26 source-only entries and three separate reference functions from 97 logical source inputs. Seven historical negative-fixture files (six full bodies and one manifest) are hash-bound source inputs only; their native regressions do not count as MIPS probe execution. Source Python is parsed as literal AST data, never imported or called.

Thirteen real objects and commands, their required aggregate members, 56 unique implementation symbols and the linked vmlinux are bound to the same independently image-bound kernel. Stable owners include mii_mgr_read/write/read_cl45/write_cl45, raether_remove, device_release_driver, reset_control_reset/assert/deassert/put, __devm_reset_control_get, esw_ioctl_init_post, esw_ioctl_init and the static mtk_esw_ioctl callback. The callback file_operations table, register_chrdev use, include translation unit and Makefile membership are separately source-bound; no standalone ioctl.o is invented. Optimized-away helpers do not require invented standalone symbols. The shipping profile requires built-in RAETH/NOR, MT7621, little endian, reset-controller and ESW support; forced ETHTOOL wrappers in the MDIO model remain disabled in the shipping profile.

The original bookkeeping, NOR admission, proc retirement, runtime DMA ownership, QDMA TX transaction and ioctl guards remain covered. DMA mappings, rings, MMIO mappings, parent-device and netdev ownership survive failed stop/idle cleanup. The remove model executes the actual driver-core release body and observes that driver-core ignores the callback return and clears drvdata; explicit non-devm ownership protects the retained graph. Selected callbacks and reference-count transitions are inert seams, not physical removal or arbitrary kernel concurrency proof.

MDIO executes bounded polling with frozen ticks and full ordered 32-bit controller commands, Clause22/45 address/data failure propagation, and selected pthread detach/indirect-transaction schedules. The model forces three ETHTOOL wrappers for error propagation coverage; they are not shipping K2P objects. The original ESW32 model keeps its historical seams and observations. The separate esw_vlan68 model executes the actual checked register/MDIO-VTCR-VLAN/IGMP and ioctl bodies, MIB output and user-copy boundaries, permission rejection, pending VLAN cleanup inventory and pre-command busy waits. It adds checked LED/storm/jumbo/link-mode control and status output paths, preserving dirty state for accepted-write errors and same/old request retry. The now-unused legacy reg_get/reg_set bodies are source-only, never described as executed. capability, uaccess, locking and hardware are inert seams. Partial hardware mutations are not atomic rollback. Runtime additionally executes the post-init error path before DMA starts. Reset-core17 retains its sequential retry observations; reset_lifecycle48 adds actual assert/deassert, optional consumer/devres/module ownership and busy provider retry paths. Separate native pthread regressions cover selected provider overlap. This board has no current shared-reset caller.

Base -Wall/-Wextra/-Werror flags remain unchanged for all preceding components. Only the MDIO and new reset_lifecycle models append -Wno-unused-parameter, and only the two ESW models append -Wno-unused-variable, -Wno-unused-parameter and -Wno-unused-but-set-variable. These exact literal component options account for synthetic seams and are checked by the independent acceptor; they do not change production compilation or suppress other diagnostics.

Early static MIPS preflight and final same-image SPI reference are mandatory. The actual compiled config must equal the embedded image config. Userspace models do not establish physical DMA drainage, real Linux callback/RTNL ABI, arbitrary scheduling, hot reset, whole-system memory pressure or efd2 first-upgrade safety. No router operation is performed.

The independent shutdown component executes complete PDMA/QDMA bounded idle, stop, IRQ retirement, close, RAETH shutdown and platform shutdown-dispatch bodies through the real driver initializer. Idle and timeout both retain every DMA/MMIO/clock and existing module/parent owner. A void shutdown callback cannot veto subsequent platform PM-domain detach or machine reset. Generic device_shutdown, registration and kernel_restart_prepare are source-only; their objects are not invented from drivers/base/dd.o. The static raether_shutdown owner is required in the existing real RAETH object, aggregate, built-in and image-bound linked kernel.

The PHY component executes the complete LEOPARD poller plus the actual inline Linux mii_resolve_flowctrl_fdx helper, including 32 full/half-duplex PAUSE/ASYM advertisement combinations, failed MDIO reads, retry and EEE clearing. Six MII/MAC definitions and two static RX/TX-bit mapping assertions are source-bound. K2P MT7621 does not start this poller; it is an explicit forced variant. Only this new model adds -Wno-unused-parameter for its inherited unused callback argument. The real escaped phy_polling_thread symbol remains required; an optimized-away standalone inline MII helper is not invented.
